Overview Read first

The code is split into two phases:

✅ Phase 1 — UI/UX (complete)

All pages, components, and mock data are built. The app runs fully without a database using MOCK_RECIPES.

🔄 Phase 2 — Backend (wired, needs your credentials)

Prisma schema, NextAuth, Server Actions, R2 upload, and OpenFoodFacts proxy are all written. You just need to plug in your API keys and run migrations.

⚠️ The app still works without completing Phase 2 — it'll just use mock data. Complete these steps when you're ready to make it real.

Step 1 Neon.tech — PostgreSQL

Neon provides a serverless PostgreSQL database with a generous free tier. It's perfect for Next.js + Prisma and supports connection pooling via PgBouncer.

  1. Go to neon.tech and create a free account.
  2. Click New Project. Name it forkable. Choose the nearest region.
  3. Once created, open the Connection Details panel (Dashboard → your project → Connection string).
  4. Copy the pooled connection string (this is your DATABASE_URL). It looks like: postgresql://user:pass@ep-xxx.us-east-2.aws.neon.tech/forkable?pgbouncer=true&connection_limit=1
  5. Also copy the direct connection string (toggle "Pooling" off). This is your DIRECT_URL. Same but without ?pgbouncer=true.
⚠️ Neon free tier pauses after 5 minutes of inactivity. Your first request after a pause will take ~2 seconds to cold-start. This is fine for development. Upgrade to a paid tier for production.

Step 2 Google OAuth

Enables "Sign in with Google" on the login and signup pages.

  1. Go to console.cloud.google.com.
  2. Create a new project (top-left dropdown → New Project). Name it Forkable.
  3. Navigate to APIs & Services → OAuth consent screen. Choose External. Fill in App name (Forkable), support email (your email), and developer contact. Save & Continue through all steps.
  4. Navigate to APIs & Services → Credentials → Create Credentials → OAuth 2.0 Client ID.
  5. Application type: Web application.
  6. Authorized redirect URIs — add both: 
    http://localhost:3000/api/auth/callback/google
https://your-production-domain.vercel.app/api/auth/callback/google
  7. Click Create. Copy the Client ID and Client Secret.

Step 3 Cloudflare R2 — Image Storage Optional for MVP

R2 stores recipe photos, profile avatars, and banner images. It's S3-compatible and has no egress fees (unlike AWS S3). Skip this step initially — the app works without it, just without image uploads.

  1. Go to dash.cloudflare.com. You need a Cloudflare account (free).
  2. In the sidebar, click R2 Object Storage → Create bucket. Name it forkable-media.
  3. In the bucket settings, enable Public access (so images load without auth). Copy the Public bucket URL — this is R2_PUBLIC_URL.
  4. Set the CORS policy for the bucket. Go to Bucket → Settings → CORS Policy → Add rule: 
    [{
  "AllowedOrigins": ["http://localhost:3000", "https://yourdomain.vercel.app"],
  "AllowedMethods": ["PUT", "GET"],
  "AllowedHeaders": ["Content-Type"],
  "MaxAgeSeconds": 3600
}]
  5. Go to R2 → Manage R2 API tokens → Create API token. Permissions: Object Read & Write, scoped to forkable-media.
  6. Copy Access Key ID, Secret Access Key, and Account ID (shown at the top of the R2 dashboard).

Step 3.5 Upstash Redis — Rate Limiting & Cache Optional

Upstash provides serverless Redis used for API rate limiting and query caching. The app works without it — an in-memory fallback kicks in automatically — but on Vercel (where each serverless instance has its own memory) Redis makes limits and caches shared and durable.

  1. Go to console.upstash.com and sign up (free tier: 500K commands/month).
  2. Click Create Database. Name it forkable, pick the region closest to your Vercel deployment, and choose the free plan.
  3. On the database page, open the REST API tab and copy UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN.
  4. Add both to .env.local and to Vercel → Project → Settings → Environment Variables.
# ── Upstash Redis (optional) ────────────────────────────────────────
UPSTASH_REDIS_REST_URL="https://xxx.upstash.io"
UPSTASH_REDIS_REST_TOKEN="AXxxx"

Step 4 Environment Variables

Create a file called .env.local in the project root (it's already in .gitignore — never commit this file).

Generate AUTH_SECRET by running:

openssl rand -base64 32

Then fill in .env.local:

# ── Database (from Step 1) ──────────────────────────────────────────
DATABASE_URL="postgresql://user:pass@ep-xxx.us-east-2.aws.neon.tech/forkable?pgbouncer=true&connection_limit=1"
DIRECT_URL="postgresql://user:pass@ep-xxx.us-east-2.aws.neon.tech/forkable"

# ── NextAuth ─────────────────────────────────────────────────────────
AUTH_SECRET="paste-your-openssl-output-here"
AUTH_URL="http://localhost:3000"

# ── Google OAuth (from Step 2) ───────────────────────────────────────
GOOGLE_CLIENT_ID="xxx.apps.googleusercontent.com"
GOOGLE_CLIENT_SECRET="GOCSPX-xxx"

# ── Cloudflare R2 (from Step 3, optional) ───────────────────────────
R2_ACCOUNT_ID="your-cloudflare-account-id"
R2_ACCESS_KEY_ID="xxx"
R2_SECRET_ACCESS_KEY="xxx"
R2_BUCKET_NAME="forkable-media"
R2_PUBLIC_URL="https://pub-xxx.r2.dev"
Quick reference — what each var does

DATABASE_URLPooled Neon connection (Prisma Client uses this at runtime)
DIRECT_URLDirect Neon connection (prisma migrate uses this — bypasses PgBouncer)
AUTH_SECRET32-byte random string for signing JWTs and cookies
AUTH_URLYour app's base URL. Change to production domain on Vercel.
GOOGLE_CLIENT_IDFrom Google Cloud Console → Credentials
GOOGLE_CLIENT_SECRETFrom Google Cloud Console → Credentials
R2_ACCOUNT_IDCloudflare Account ID (top of R2 dashboard)
R2_ACCESS_KEY_IDR2 API token access key
R2_SECRET_ACCESS_KEYR2 API token secret key
R2_BUCKET_NAMEName of your R2 bucket (e.g. forkable-media)
R2_PUBLIC_URLPublic URL prefix for serving images (e.g. https://pub-xxx.r2.dev)

Step 5 Run Migrations & Seed

With .env.local filled in, create the database tables:

# 1. Create all tables from schema.prisma
npm run db:migrate
# (it will prompt for a migration name — type "init" and press Enter)

# 2. Seed dev data (mock users, a sample recipe, tags)
npm run db:seed

# 3. Optionally open Prisma Studio to browse the data
npm run db:studio
✅ After this, the app will use real PostgreSQL data instead of mock JSON. You can sign in with: shrey@forkable.dev / devpassword123

If you need to reset and re-seed (e.g. during development):

npx prisma migrate reset    # drops all tables, re-applies migrations, re-runs seed

Step 6 Deploy to Vercel

  1. Push your code to GitHub (see Step 7).
  2. Go to vercel.com → New Project → Import from GitHub.
  3. Select your forkablec repo. Framework preset: Next.js.
  4. In the Environment Variables section, add all the vars from Step 4 (same values, but change AUTH_URL to your Vercel domain).
  5. Click Deploy. First deploy takes ~2 minutes.
  6. After deploy, go back to Google Cloud Console and add the Vercel URL to your OAuth redirect URIs.
⚠️ For the DIRECT_URL on Vercel: Neon provides a "non-pooled" connection string. Use that for DIRECT_URL and the pooled one for DATABASE_URL.

Step 7 Connect GitHub

Your repo is already at github.com/shreywy/forkablec.

# Push all the Phase 2 changes
git add -A
git commit -m "feat: Phase 2 backend — Prisma schema, NextAuth, Server Actions, R2, OFFs"
git push origin main

Then follow Step 6 to deploy to Vercel (it auto-deploys on every push to main).

Useful Scripts

npm run dev          # start dev server (localhost:3000)
npm run build        # production build
npm run db:generate  # regenerate Prisma Client after schema changes
npm run db:migrate   # create and apply a new migration
npm run db:push      # push schema changes without a migration (dev only)
npm run db:seed      # seed the database with mock data
npm run db:studio    # open Prisma Studio (visual DB browser)
